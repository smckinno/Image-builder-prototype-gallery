Firewall UI Comparison

iptables rule builder vs firewalld zone dashboard — interactive prototypes

Prototype · not production

Two mental models, two UIs

The iptables approach treats firewall config as an ordered list of match→action rules. firewalld wraps that complexity in zone-based trust levels with service toggles. Each mental model calls for a fundamentally different interface.

iptables

Rule Builder

Primary pattern: draggable table where each row is a rule. First match wins — rule order is everything.

  • Drag-to-reorder rows (priority matters)
  • Each row: direction, protocol, source/dest, port, action
  • Default policy bar at the bottom
  • Traffic simulator: "would this packet get through?"
  • Feels like: a spreadsheet / AWS Security Groups
Image Builder · firewalld

Blueprint Form

Primary pattern: form → blueprint output. Toggle services, add ports, preview the config that gets baked into the image.

  • Service toggles: enable SSH, HTTPS, Cockpit, etc.
  • Additional ports for non-standard services
  • Explicitly disabled services (override distro defaults)
  • Live blueprint preview in JSON or TOML
  • Feels like: a wizard step in Image Builder
Try both tabs. The iptables view is a raw rule table with drag-to-reorder and a traffic simulator. The firewalld view is an Image Builder form — toggle services, add ports, and watch the blueprint update live.
iptables-style

Firewall Rule Builder

Rules are evaluated top-to-bottom — first matching rule wins. Drag rows to reorder priority. The default policy catches anything that doesn't match.
